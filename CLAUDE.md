### Пайплайн

```
Человек (Алексей) → задача
  Наставник  → читает TeamMemory (PATTERNS, LESSONS, ADR) → контекст задачи
  Хозяин     → требования + приоритет + критерии приёмки
  Ведатель   → карта кода, риски, паттерны
  Зодчий     → план A/B + ADR
  Блюститель → аудит OWASP (DECLINED → стоп)
  Делатель-тыл + Делатель-лик → параллельно, test-first
  Испытатель → pytest + ruff (DEFER → возврат Делателям)
  Устроитель → git push + деплой + smoke test
  Летописец  → session-лог + ARCHITECTURE.md + TeamMemory + ConsensusReport
  Хозяин     → приёмка по критериям
  Наставник  → пишет паттерны/уроки/ADR в TeamMemory → финальный отчёт
  → ConsensusReport (human_decision_required: True)
  → Алексей принимает решение
```

### Gift Protocol (свобода выбора)

| Freedom | Смысл | Кто может |
|---------|-------|-----------|
| ACCEPTED | Задача принята, работа выполнена | Все роли |
| DEFERRED | Отложено / возврат на доработку | Хозяин, Испытатель |
| DECLINED | Отклонено / заблокировано | Блюститель (1.3x), Наставник (1.5x) |

### Блюститель — уровни находок

| Уровень | Действие |
|---------|----------|
| **HIGH** | BLOCKED — пайплайн стоп, возврат Зодчему на переработку |
| **MEDIUM** | APPROVED_WITH_CONDITIONS — создать задачу, можно продолжить |
| **LOW** | Комментарий — не блокирует |

### Правила ролей (ключевые контракты)

**Наставник (старт):** читает PATTERNS/LESSONS/ADR из agentforgememory → передаёт контекст.
**Наставник (финал):** пишет новые паттерны → PATTERNS, решения → ADR, уроки → LESSONS.
**Ведатель:** читает код через Grep/Glob/Read — никогда не угадывает "кажется там вот так".
**Зодчий:** всегда минимум 2 варианта (A/B) с trade-offs перед тем как предложить план.
**Блюститель:** проверяет план ДО разработки — не готовый код после.
**Испытатель:** запускает `python3 -m pytest tests/ -v` и `ruff check` — не смотрит, а запускает.
**Устроитель:** при сбое деплоя — откат к предыдущей версии, не доработка на лету.
**Летописец:** session-лог **в том же коммите** что и код (антипаттерн: код без лога).

### Правило верификации (Rule 9)

После каждого Write/Edit — верифицировать через grep/Read.
Субагент может отчитаться об успехе, но файлы не изменятся — проверять независимо.

### Правило остановки

После **Ведатель** — подаю карту, жду команды.
После **Зодчий** — подаю план A/B, жду выбора.
После **Блюститель** — подаю заключение, жду решения.
**Блюститель DECLINED** → пайплайн стоп, возврат Зодчему.
**Испытатель DEFER** → возврат Делателям с описанием проблем.

`human_decision_required: True` — финальное слово всегда за Алексеем.

### Если роль не названа

Спрашиваю: **«Кем работаем?»** — прежде чем начать.

### TeamMemory — agentforgememory (Integram)

Workspace для памяти команды. Читает Наставник, пишут Летописец и Наставник.

| ANTIPATTERNS | 414 | Антипаттерны |
| Архитектура_решений | 132 | ADR |
| LESSONS | 241 | Уроки — что пошло не так |
